# Solo Silo: Conventional Rockets

**Minecraft Java 1.21.1 / Fabric / 0.3.0-silo-rc1**

Компактный вертикальный контейнер с одной обычной ракетой и ручным целеуказателем. Вдохновлён игровой механикой Solo Silo: поставить, зарядить, навести метку, быстро ударить по цели.

Это **полный исходный проект для GitHub Actions**, не готовый JAR. Новый RC ещё не собран на настоящем Minecraft/Fabric classpath и **в игре не проверен**. Пройденные проверки перечислены в `VALIDATION.md`.

## Что изменилось относительно предыдущего ZIP

- Нет колёсной машины, огромного контейнера и долгого развёртывания. Пусковая около **3,8 блока высотой**, площадка **3 x 3**.
- Одна компактная ракета, без отделения ступеней, космической дуги и конечного боевого блока.
- Нет координатного пульта. Есть **ручной целеуказатель с привязкой к конкретной пусковой**.
- Сервер считает полёт и проверяет отрезок движения на столкновение каждый тик: стены, земля и сущности могут перехватить ракету.
- Наведение обновляется при удержании ПКМ. Отпустил: ракета продолжает к последней принятой метке, а не исчезает.
- Обычный взрыв: короткая огненная вспышка в мире, пыль, выброс грунта, искры, обломки и небольшой кратер.
- **Нет ядерного гриба, огромного светового купола, экранного ослепления, трёхступенчатого полёта и спёкшегося стекла.**
- Реалистичная визуальная стилистика, но **игровая физика**. Не заявляется точная модель какого-либо реального комплекса.

Мод сохраняет внутренний идентификатор `topol`, чтобы не менять все имена ресурсов. В игре и JAR название теперь **Solo Silo**.

## Быстро собрать

1. Распакуй архив и загрузи **содержимое папки проекта в корень чистого GitHub-репозитория**.
2. Обязательно включи скрытую папку `.github`.
3. **Actions → build** запускается после push или вручную через Run workflow.
4. После успешной сборки скачай артефакт **solo-silo-jar**. JAR: `solo-silo-0.3.0-silo-rc1.jar`.

Это **замена проекта целиком**, не патч поверх старой альфы или RC. Сохрани старый репозиторий/архив отдельно, не смешивай исходники.

Не ставь старый Topol и новый Solo Silo одновременно: у них одинаковый mod ID. Не используй мир со старой огромной пусковой как первый тест. Совместимость старых сущностей не предусмотрена; файл старых полётов `topol-flight-state.json` новой версией не читается.

### Версии

- Minecraft 1.21.1.
- Java 21, Fabric Loader 0.16.14 или новее.
- Fabric API 0.116.4+1.21.1.
- Yarn 1.21.1+build.3, Gradle 8.14.3, Loom 1.11-SNAPSHOT.

Actions сам ставит JDK и Gradle. Wrapper не нужен. Snapshot Loom сохранён от ранее собранного инструментария; он не делает сборку полностью воспроизводимой и не доказывает совместимость нового кода.

Локально, если установлены Java 21 и Gradle 8.14.3 и доступны Maven-репозитории:

```sh
python3 tools/validate_assets.py
gradle build --no-daemon --stacktrace
```

## Установка и первый запуск

JAR и Fabric API положить в `mods` отдельного профиля Minecraft 1.21.1. На сервере мод должен быть **и у сервера, и у клиентов**.

**Первый запуск только в копии мира**, без шейдеров и дополнительных рендер-модов.

```mcfunction
/give @s topol:launcher
/give @s topol:missile
/give @s topol:designator
```

1. Подготовь ровную площадку **3 x 3 блока**, с пространством минимум **17 блоков вверх**.
2. Поставь контейнер ПКМ по верхней стороне блока.
3. Держа предмет ракеты, нажми ПКМ по контейнеру. Новая пусковая пустая, включая creative.
4. ПКМ по контейнеру пустой рукой выдаёт привязанный целеуказатель один раз. Или используй свой целеуказатель на контейнере для привязки.
5. Отойди, возьми пульт и наведи на землю, постройку или сущность.
6. **Удерживай ПКМ примерно полсекунды на допустимой цели: это запускает ракету. Отдельного второго подтверждения нет.**
7. Продолжай удерживать ПКМ, чтобы корректировать метку. Поворот ракеты не мгновенный.
8. Отпускание ПКМ фиксирует последнюю принятую цель. После отпускания повторно перехватить этот выстрел нельзя.
9. Для следующего выстрела отпусти ПКМ, вернись, заряди новую ракету. Пульт можно использовать повторно.

Только владелец или оператор может управлять контейнером при `ownerLock: true`.

Чтобы забрать контейнер: подожди завершения стартового движения, **присядь и ударь его**. Контейнер и оставшаяся загруженная ракета вернутся предметами. Пульт после повторной установки нужно привязать заново.

### Если метка не принимается

- Допустимая дальность по умолчанию: **32-1024 блока от пусковой**.
- Пусковая и игрок должны быть в одном измерении; пусковая должна оставаться в загруженном чанке.
- Разница высоты цели и пусковой ограничена 128 блоками.
- Целеуказатель требует реального пересечения с блоком или сущностью, а не просто направления в небо.
- Прицел не просматривает незагруженные чанки и не генерирует весь горизонт.
- Если метка пропала после пуска, ракета сохраняет последнюю допустимую точку.
- Высокие препятствия не обходятся автоматически: ракета может врезаться в них.

## Скорость

Измерено **в независимом тесте игровой траектории**, для неподвижной цели на уровне земли, без препятствий, задержек сети и загрузки чанков:

| Дистанция | Время после запуска |
|---|---:|
| 32 блока | 1,50 с |
| 128 блоков | 1,70 с |
| 256 блоков | 2,15 с |
| 500 блоков | 2,75 с |
| 1000 блоков | 3,90 с |

К этому добавляется примерно полсекунды удержания перед запуском. В этих тестах высшая точка около **34 блоков над стартом**, не сотни километров. Максимальная игровая скорость: 22 блока за тик. При сближении ракета замедляется, чтобы не бесконечно кружить вокруг метки.

Это результаты математического теста, **не замер FPS/TPS или игрового видео**. Загрузка чанков может приостановить полёт; после длительного ожидания ракета прекращает полёт без разрушения. Предельное время активного полёта: 12 секунд.

## Взрыв и сохранность мира

По умолчанию:

- Кратер: радиус **6 блоков**, номинальная глубина **3** плюс неровность.
- Зона разрушения: **16 блоков**.
- Зона пыли/поверхностного выжигания: до **24 блоков**.
- Bedrock и служебные блоки защищены.
- Контейнеры с инвентарём удаляются **без выпадения содержимого**.
- Не-живые сущности внутри прошедшего фронта, в том числе лут, рамки и вагонетки, могут удаляться.
- Изменения блоков обрабатываются порциями, не одним огромным вызовом взрыва.

**Отката разрушений внутри мода нет.** Перед тестом выключи игру/сервер и сохрани всю папку мира. Для восстановления используй полную копию, не смесь отдельных region-файлов.

Нет интеграции с защитой участков/claim-модами. Не используй в общем мире без разрешения администратора. Creative не защищает постройки.

## Настройки

После первого запуска: `config/solo-silo.json`. Настройки старого `topol.json` специально не используются, чтобы не унаследовать гигантские радиусы.

Пример находится в `config/solo-silo.example.json`. Редактируй при закрытой игре/сервере.

- `enableDestruction: false`: попадания дают только небольшой визуальный эффект, без разрушения/урона этой системы. Сохранённые работы приостанавливаются, не отменяются.
- `ownerLock`: защита управления чужими игроками.
- `minRange`, `maxRange`: игровая дальность.
- `craterRadius`, `craterDepth`, `destructionRadius`, `thermalRadius`: размеры обычного воздействия. Есть жёсткие ограничения, старые огромные значения обрезаются.
- `particleLimit`, `effectDensity`, `effectsDistance`: клиентская нагрузка.
- `enableCameraShake`, `cameraShake`: тряска только камеры, не направления прицела.
- `soundVolume`: громкость звуков мода.
- `blockChangesPerTick`, `blockChecksPerTick`, `blastMillisPerTick`: бюджет работы по блокам.

## Проверки и ограничения

- Пройдено **8 независимых Java-тестов** и статическая проверка ресурсов.
- Java-код проверен на синтаксис/типы с частными минимальными тестовыми API. Это **не настоящая компиляция Fabric**.
- Настоящая сборка нового RC, dedicated server и запуск Minecraft **не выполнялись**. Нужны GitHub Actions и игровой прогон.
- Sodium, Iris, Fabulous и шейдерпаки не проверены. Начни с Fast/Fancy без них.
- Дым выполнен собственными спрайтами; это не объёмная симуляция жидкости. Дальние эффекты масштабируются относительно камеры.
- Ракета имеет серверное столкновение по отрезку, а не точную физическую коллизию каждого полигона.
- Пыль и крышка имеют клиентскую физику; земля, ракета и урон контролируются сервером.
- Пусковая не требует 20 секунд развёртывания, не ездит и не закапывается автоматически в землю. Это отдельно устанавливаемый компактный контейнер.
- Наведение работает по текущей точке метки, а не по автоматическому сопровождению цели.
- Все звуки и эффекты ракеты собственные. Обычные события самой игры, например звуки смерти мобов, не заменяются.
- Предпросмотр `docs/silo-preview.png` создан программным рендерером, **не в Minecraft**. Ручной предмет использует упрощённую 3D JSON-модель; круглый объектив mesh-превью является визуальным референсом.

## Сохранение, удаление и лицензия

Полёты и очереди кратеров: `solo-silo-state.json` в корне мира, предыдущая копия `.bak`. Сохранение каждые 2 секунды, при пуске и штатном завершении. Аварийный выход может откатить последние секунды; это не транзакционное сохранение всей карты. При повреждённом файле он остаётся нетронутым, загрузка/запись очереди отключается с ошибкой в логе.

Перед удалением JAR сделай копию мира, дождись завершения полётов и работ, убери предметы/контейнеры. Собственные блоки без мода станут отсутствующим содержимым. Восстановление мира: из полной резервной копии.

Код и оригинальные процедурные ассеты: MIT. Материалы Helldivers 2 не извлекались и не включались, референс использован только для игровой идеи. Minecraft не поставляется. См. `THIRD_PARTY_NOTICES.md`.

Для редактирования ассетов: `python tools/gen_silo.py` (NumPy, Pillow, SciPy, ffmpeg/libvorbis, DejaVu Sans). Для обычной сборки генерация не требуется.
