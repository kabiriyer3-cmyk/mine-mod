# Topol: Cinematic Launcher

**Minecraft Java 1.21.1 • Fabric • 0.2.0-rc1**

Полный исходный проект игрового мода. Это не готовый JAR и не подтверждённый игровой релиз: финальную сборку выполняет GitHub Actions, проверка в Minecraft ещё нужна. Статус проверок: [docs/VALIDATION.md](docs/VALIDATION.md).

## Что реализовано

- Неподвижная восьмиосная пусковая: установка предметом, четыре опоры, подъём контейнера, телескопические гидроцилиндры, маяки, сброс крышки. Управления ездой нет.
- Русский и английский пульт: координаты X/Z, учебный или разрушительный режим, подготовка и отдельное подтверждение пуска с серверным токеном.
- Холодный старт, включение двигателя после выхода из контейнера, три видимые ступени, отделение частей, самостоятельный конечный аппарат и финальное снижение.
- Собственные меши и атласы 2048 px с LOD 1024/512. Дым и огонь: атласы 2048 px, по 64 спрайта. Новые текстуры грунта: 256 px.
- Свои дым, горячий факел, искры, обломки, пыль, вспышка, расширяющийся фронт и поднимающееся грибовидное облако. Весь звук синтезирован для проекта; есть задержка распространения и ближний/дальний рёв.
- Настоящее изменение блоков: чаша кратера, вал выброса, разрушение вокруг, выжженная земля и спёкшееся стекло. Работа разбита по тикам, визуальный фронт следует за серверной обработкой.
- Сохранение активных полётов и незаконченных кратеров, синхронизация наблюдателей, защита управления по владельцу.
- Предметы в творческой вкладке боя и два рецепта для выживания.

**Полёт здесь игровой и постановочный.** Масштаб, длительность, форма траектории и эффекты подобраны для Minecraft. Это не инженерный симулятор реальной ракеты. Старое экспериментальное полётное ядро альфы в этот проект не включено.

## Собрать в GitHub Actions

1. Распакуй ZIP.
2. Загрузи **содержимое проекта в корень чистого репозитория**, включая `.github/workflows/build.yml`. Если заменяешь альфу, сначала сохрани её копию, затем замени проект целиком: ZIP не является патчем поверх старых исходников.
3. Открой **Actions → build**. Запуск происходит после push; также доступен **Run workflow**.
4. После зелёной сборки скачай артефакт **topol-jar**. Внутри будет `topol-0.2.0-rc1.jar`.
5. В артефакте **test-report** лежит HTML-отчёт тестов.

JDK 21 и Gradle 8.14.3 устанавливаются самим workflow. Wrapper не требуется для Actions. Ассеты уже включены, их генераторы при сборке не запускаются.

Версии: Fabric Loader 0.16.14, Fabric API 0.116.4+1.21.1, Yarn 1.21.1+build.3, Loom 1.11-SNAPSHOT. Инструментарий сборки сохранён от ранее собранной альфы; это не подтверждает сборку новых классов. Loom использует тот же snapshot-канал, а не неизменяемый релиз.

Локальная сборка при наличии JDK 21, Gradle 8.14.3 и доступа к Maven:

```sh
python3 tools/validate_assets.py
gradle build --no-daemon --stacktrace
```

## Установка

1. Создай отдельный профиль Minecraft **1.21.1** с Fabric Loader **0.16.14 или новее**.
2. Положи JAR мода и Fabric API для 1.21.1 в папку `mods` этого профиля.
3. Для сервера те же моды нужны **и на сервере, и у каждого клиента**.
4. Первый запуск: без шейдеров, в режиме графики Fast или Fancy, в **копии тестового мира**.

GeckoLib, OptiFine и сторонние библиотеки анимации не нужны.

## Первый пуск

Сначала выбери **учебную нагрузку**, чтобы проверить механику без разрушения мира.

```mcfunction
/give @s topol:launcher
/give @s topol:missile
```

1. Подготовь ровную свободную площадку примерно **27 × 5 блоков**, с воздухом до высоты 27 блоков над ней. Лучше Superflat.
2. Поставь пусковую ПКМ по верхней стороне блока. Направление привязывается к четвертям оборота игрока.
3. Держа предмет ракеты, нажми ПКМ по пусковой. Новая пусковая всегда пустая, в творческом режиме тоже.
4. Нажми ПКМ пустой рукой: откроется пульт.
5. Нажми **«Развернуть»** и дождись готовности: около 20 секунд.
6. Введи X/Z цели. По умолчанию разрешено от **128 до 24 000 блоков** от основания ракеты. Высота цели определяется по поверхности.
7. Выбери **«Учебная / без взрыва»** либо **«Разрушительная»**.
8. Нажми **«Подготовить пуск»**, затем **«Подтвердить пуск»** в течение 5 секунд.
9. Последовательность крышки и запуска занимает 3 секунды. Далее следует холодный выход из контейнера, затем зажигание. Весь игровой полёт занимает примерно 100-190 секунд, в зависимости от дистанции.
10. После пуска сверни пусковую, заряди новый предмет ракеты и повтори.

Верхний правый индикатор рядом со стартом или целью показывает фазу, игровую высоту, скорость и оставшееся время. Взгляд на ракету не требуется для продолжения серверного полёта.

Чтобы забрать комплекс: **сверни его, зажми приседание и ударь**. Вернутся предмет пусковой и оставшаяся ракета, если она была загружена. Чужую пусковую может обслуживать только владелец или оператор, если `ownerLock` включён.

## Разрушения и резервные копии

**Разрушительный режим действительно удаляет постройки и содержимое контейнеров. Отмены взрыва и автоматического восстановления мира нет.**

- Перед тестом закрой игру/сервер и скопируй целиком папку мира, включая измерения и данные игроков.
- Радиусы по умолчанию: **64 блока кратер, 160 разрушение, 240 термическая зона**. Глубина чаши: 26 блоков. Это игровые параметры.
- В чаше удаляются обычные блоки независимо от прочности; во внешней зоне учитывается игровое сопротивление блока.
- Bedrock и другие неразрушимые блоки по умолчанию сохраняются. Барьеры, командные и структурные блоки защищены отдельно.
- Содержимое сундуков не выпадает. Разброса миллионов предметов нет. Не-живые сущности в зоне фронта, включая предметы, вагонетки и активированный TNT, удаляются.
- Разрушение большого участка не мгновенное. Ограничен объём изменений и время работы за тик; создание и загрузка новых чанков, обработчики чужих модов и сохранение мира всё равно могут нагружать сервер.
- Мод **не интегрирован с claim/protection-плагинами**. Не включай разрушения в общем мире без разрешения его администратора.

Для восстановления закрой игру/сервер, сохрани копию текущего повреждённого мира, затем верни **всю резервную копию**, не отдельные region-файлы вперемешку.

## Настройки

После первого запуска создаётся `config/topol.json`. Пример: [config/topol.example.json](config/topol.example.json).

Изменяй настройки при закрытой игре/сервере; нужен перезапуск.

| Настройка | Значение по умолчанию | Назначение |
|---|---:|---|
| `enableDestruction` | `true` | Разрешает новые разрушения; при `false` сохранённые работы приостанавливаются |
| `ownerLock` | `true` | Владелец или оператор управляет пусковой |
| `breakUnbreakable` | `false` | Разрешение разрушать неразрушимые блоки внутри зоны; служебные блоки всё равно защищены |
| `maxConcurrentFlights` | `4` | Максимум полётов |
| `maxConcurrentBlasts` | `2` | Одновременно обрабатываемые кратеры |
| `blockChangesPerTick` | `2500` | Общий бюджет изменений блоков |
| `blockChecksPerTick` | `12000` | Общий бюджет проверок блоков |
| `blastMillisPerTick` | `7` | Дополнительный временной предел обработки |
| `particleLimit` | `2400` | Лимит обычных частиц; облака имеют отдельный ограниченный набор спрайтов |
| `effectDensity` | `1.0` | Плотность частиц, от 0.1 до 1.0 |
| `effectsDistance` | `6000` | Дальность визуальных эффектов |
| `enableFlash` | `true` | Экранная вспышка |
| `flashStrength` | `0.65` | Сила вспышки |
| `enableCameraShake` | `true` | Тряска только камеры, не прицела игрока |
| `cameraShake` | `0.7` | Сила тряски |
| `soundVolume` | `1.0` | Громкость собственных эффектов |

На слабом ПК начни с `particleLimit: 800`, `effectDensity: 0.4`, `meshDebrisLimit: 12`. При просадке TPS уменьши `blockChangesPerTick` и `blastMillisPerTick`. Кратер будет обрабатываться дольше, не станет меньше.

`enableDestruction: false` **не восстанавливает** уже разрушенные блоки. Незаконченные сохранённые работы приостанавливаются и продолжатся, если снова включить настройку. Полёты, попавшие в цель при выключенной настройке, дают учебный эффект.

## Сохранение и удаление

- Состояние пусковой сохраняется вместе с сущностью Minecraft.
- Полёты и очередь кратеров: `topol-flight-state.json` в корне мира. Есть предыдущая копия `.bak`; запись атомарная, когда файловая система это поддерживает.
- Автосохранение очереди: каждые 10 секунд и при штатном завершении сервера. При аварии возможен откат последних секунд. Это не транзакционная резервная копия всей карты.
- Для удаления мода сначала сделай резервную копию мира, убери пусковые и предметы, дождись завершения работ и закрой игру. После удаления JAR собственные блоки и сущности исчезнут/станут отсутствующим контентом. Откат мира делается из полной копии.

## Ограничения, которые важно знать

- **В Minecraft ещё не проверено.** Сборка нового RC на настоящем classpath Minecraft/Fabric также здесь не запускалась. Локальная проверка Java с тестовыми API не заменяет GitHub Actions.
- Полёт программный, с кинематографической траекторией. Это не RK4-модель реальной МБР, не аэродинамический расчёт и не моделирование реального взрывного устройства.
- Контейнер и ракета размером в десятки игровых блоков; Minecraft-масштаб намеренно сохранён. Коллизия пусковой упрощённая, прямоугольная. Отделившиеся детали имеют только клиентскую физику.
- Полёт не загружает всю трассу. Дальние эффекты проецируются ближе к камере с сохранением углового размера. Это экономит чанки, но далёкое перекрытие горами и взаимодействие с туманом приблизительные.
- Дым сделан сортируемыми спрайтами, не объёмным fluid solver. Нет физической рефракции воздуха, PBR-карт, радиации или долгосрочной симуляции осадков.
- У ракеты и взрыва нет вызовов стандартных частиц, ванильного звука взрыва или `createExplosion`. Обычные события самой игры, например смерть мобов, не заменяются.
- Жидкости, осыпание блоков и соседние обновления вокруг кратера упрощены. Чужие моды могут реагировать на замену блоков по-своему.
- Sodium, Iris, Fabulous и конкретные шейдерпаки не проверены. Сначала проверь без них, затем добавляй по одному.

Полный ручной прогон: [docs/TEST_CHECKLIST.md](docs/TEST_CHECKLIST.md).
